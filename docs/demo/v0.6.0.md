# Chirps v0.6.0 デモ＆実行結果

## 目的

alopex-toolの機能デモ／結果記録方式を参考に、Chirps v0.6.0で利用可能になった機能を、
固定シーン・コマンド・終了コード・raw log・JSON結果で再実行できるようにする。

## 実行

軽量なマルチノードread/writeだけを実行する:

```bash
python3 scripts/demo/v0_6/demo.py --scenario quick --writes 12 \
  --output docs/demo/results/v0.6.0/quick
```

v0.6.0機能シーンをすべて実行する:

```bash
python3 scripts/demo/v0_6/demo.py --scenario all \
  --output docs/demo/results/v0.6.0/<run-id>
```

marimo UIで3ノード読み書きを実行する:

```bash
python3 -m venv /tmp/chirps-marimo
. /tmp/chirps-marimo/bin/activate
pip install -r scripts/marimo/requirements.txt
marimo edit scripts/marimo/chirps_v06_multinode_rw.py
```

## 最新実行結果

ローカルで`--scenario quick --writes 6`を実行した結果:

- leader: node 1
- writes committed: 6/6
- node-1/node-2/node-3 reads: 各6 keys
- read consistency: `true`
- elapsed: 約527 ms

この結果はMockNetwork上の1プロセス内3論理ノードによる機能証跡であり、物理3ノード性能、実ネットワーク障害、
TiKV RawKV/YCSB性能を主張しない。性能比較は環境校正済みの専用evidence手順に従う。

## TiKV等との比較境界

このデモはread/write整合性を確認するもので、TiKVのYCSB READ/UPDATE OPSと同一指標ではない。
比較測定を行う場合は、対象環境でTiKVを先に実測し、payload、client数、node数、network、warmup、測定区間、
error/timeout、resourceを対応付けた別artifactを作成する。公開ベンチマーク値を絶対閾値にしない。
