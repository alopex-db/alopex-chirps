# Chirps v0.7.0 release evidence

この文書は、Chirps v0.7.0 候補に対する証拠の配置表です。候補と証拠はまだ組み立てられておらず、この文書はリリース判断を記録しません。

## 先に読むもの

- 機械可読な契約は [`v0.7.0-evidence-schema.json`](v0.7.0-evidence-schema.json) です。
- 検証器は `scripts/release/verify-v0.7-evidence.py` です。
- 実際の候補、bundle、証拠index、および個別証拠は、外部の不変な保存先に置きます。この文書には、内容アドレスで固定されたパスと SHA-256 だけを追記します。
- この文書は機械可読証拠の投影です。この文書と検証済みindexが食い違う場合、検証済みindexを正とします。

自己検査は将来の証拠を必要としません。

```console
python3 scripts/release/verify-v0.7-evidence.py \
  --self-test docs/release/v0.7.0-evidence-schema.json
```

候補を組み立てた後は、内容アドレスで固定したindexを検証します。

```console
python3 scripts/release/verify-v0.7-evidence.py /immutable/path/evidence.json
```

## 証拠のライフサイクル

| 成果物 | 所有する情報 | 作成時点 | 置換規則 |
|---|---|---|---|
| `candidate.json` | source、Iggy、仕様、model、設定、tool、環境、server、package graph、performance plan の固定identity | release candidate freeze | 内容が変わる場合は新しい候補として作成し、上書きしない |
| `bundle.json` | 候補に属する全artifactの順序付きinventory | 全証拠の収集後 | artifactの追加・変更時は新しいbundleを作成する |
| `evidence.json` | schema、candidate、bundle、各artifactのdigest binding | bundle作成後 | 参照先またはdigestが変わる場合は新しいindexを作成する |
| この文書 | 人が確認するためのindex投影 | 機械検証後 | 検証済みの外部パスとdigestだけを追記する |

外部証拠の欄は、候補freeze前には空のままにします。credentialは参照名だけを記録し、token、password、private key、credential valueを候補、bundle、indexへ保存しません。

|---|---|---|
| candidate | 未作成 | 未作成 |
| bundle | 未作成 | 未作成 |
| evidence index | 未作成 | 未作成 |

## 修正中は対象を絞り、リリース前に全体を検証する

Codexは修正中、変更した責務を直接確認する target から実行します。リリース候補のソースが確定した後は、workspace 全体の test、build、Clippy、fmt、doc と feature matrix、API・wire 互換性、必須の E2E・性能・公開検証を実行します。局所テストの成功だけではリリース条件を満たしません。

各 target の一時出力は、実行記録を保存してから削除します。共有キャッシュは他の担当者の利用が終わるまで保持し、証拠ファイルと区別します。後続 target の正否は、その実行で取得した結果から判断します。

| 変更した責務 | 実行 target | この target が保証すること | 実行条件と出力上限 |
|---|---|---|---|
| compatible source provenance | `scripts/verify-compatible-iggy-patch.sh --source-reconstruction --require-iggy-clean` | baseline からの bundle が指定 commit、tree、lockfile、toolchain、manifest binding を再構築すること | source/manifest を変更した時だけ。短命の reconstruction directory を verifier が削除する。 |
| production server identity | `scripts/build-compatible-iggy.sh --verify-reproducible` | fixed source/toolchain で clean build を二回行い、production binary digest が一致すること | server source、toolchain、manifest、Docker metadata を変更した時だけ。一時 target は約1.2 GiB 以下で builder が削除する。 |
| durable startup と append response | `tests/e2e/scripts/run-v07-lane.sh --lane fault --target durable_send` | startup の message/index sync と append の wire-write/journal-flush/response failpoint が指定の durable result を保つこと | attested test artifact と runner trust anchor の確定後に一回。一時 E2E target は終了時に削除する。 |
| 他の durable 契約 | 対応する単一 target | creation、checkpoint、shutdown、metadata recovery の各責務を個別に示すこと | その責務の実装または fixture が変わった時だけ。`--materialized-all` は単一責務の代替にしない。 |

Codexは、production binary の再現 build を artifact identity の RC qualification とし、機能回帰を探すために繰り返しません。Codexは、focused prerequisite が失敗した場合、その target を修正・再実行するまで広い lane を開始しません。

## シナリオmatrix

### Fault、restart、delivery

証拠は、undelivered、effect-before-checkpoint、old/new resource epoch、committed checkpoint、timeout、shutdown、redelivery、およびfresh-process recoveryを区別します。terminal CAS winnerは一つとし、stale ownerまたはstale attemptはcheckpointを進めません。証拠はexactly-once effectを主張しません。

### Retention、compaction、capacity

証拠は、production manifestのhigh watermark、oldest retained、expected offset、resource epochを独立に記録します。証拠は曖昧なcurrent offsetから欠損を推定せず、offsetをclampしません。compaction証拠は全barrier imageとreplay identityを固定し、capacity証拠は全hard boundとreserveを同一設定digestへ結びます。

### Formal model

証拠は承認済みmodel inventoryを一つのmodel digestへ束ねます。最低限、durable lifecycle、delivery arbitration、checkpoint recovery、shutdown safetyを含み、実行したcheckerと設定をtool/configuration digestへ結びます。

### Performance

証拠は候補identityと環境identityを固定し、同一boundaryのbaselineとcandidateを比較します。A/A校正、事前固定したbound、全metric vector、safety override、environment scopeの欠損は受理しません。測定不能または取消済みのcellを成功として扱いません。

## 公開前の境界

- この文書はtag、push、publish、promotionを許可しません。
- packageの存在確認だけでは、機能、互換性、性能の証拠になりません。
- 後から成功したrunは、以前の失敗または未完了runを上書きしません。
- 候補、設定、環境、artifact、bundle、schemaのdigestが混在する集合は受理しません。
- 公開判断は、この文書ではなく、別途定義された承認手続きが全機械可読証拠を確認した後に行います。
