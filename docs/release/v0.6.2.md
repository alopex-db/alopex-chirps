# v0.6.2 リリース受入契約

Release readiness: READY

この文書は Issue #33 / #35 の要求、実装、検証結果を同じ release candidate に固定する受入契約です。表の要件は、機能の存在ではなく、壊れた場合に利用者が観測する失敗モードで記述します。

v0.6.2 が達成した範囲は QUIC flow-control と connection admission（idle
eviction を含む）およびその transport metrics である。`READY` は
`specs/chirps-memory-spec.md` 全体の達成を意味しない。node-wide memory budget、
profile 別 buffer、統合 eviction、health check、0-RTT、certificate cache、mTLS、
物理障害復旧は当時の契約に含めず、後続版または別の証跡へ残した。

## 変更影響レビュー

- 公開 API: `TransportConfigV04` に additive な QUIC window、stream、idle、connection limit fields と `file_transfer_performance()` / `to_quinn_transport_config()` を追加した。既存の struct update 利用は維持する。
- wire / persistence: 変更なし。
- 設定・性能: 既定 flow-control は v0.5.2 の最終性能測定で使った 16 MiB stream / 64 MiB connection / 64 MiB send / 256 uni streams。Quinn の既定値は 100 Mbps・100 ms 向けのため、この値を default として高帯域経路の既存性能を落とさない。idle timeout は Quinn 既定の 30 秒、keep-alive は既存挙動を変えない `None`。
- 接続退避: max connections は 64。満杯時の新規 peer は QUIC close code 1 相当の application close で拒否し、既存 peer は保持する。idle timeout 到達時は map から削除して close し、reconnect worker が seed を再試行できる。
- rollback: `max_connections`、window、idle、keep-alive は設定で従来相当へ戻せる。wire / persistence の rollback 手順は不要。
- セキュリティ: transport memory を bounded にするが、外部 security audit や物理攻撃モデルの追加主張はしない。
